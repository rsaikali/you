# CLAUDE.md — You

## What is this?

**You** is a single-page web app with no backend.
The user copies a prompt, pastes it into their favourite AI (ChatGPT, Claude, Gemini…), gets back a JSON profile, pastes it into the app, and a profile card is rendered entirely client-side.

Deployed at: `you.saikali.fr`

---

## Stack

| Layer     | Technology                                |
|-----------|-------------------------------------------|
| Frontend  | Pure vanilla HTML / CSS / JS (no framework) |
| Fonts     | Quicksand + IBM Plex Mono (Google Fonts)  |
| Server    | Caddy 2 (Alpine Docker image)             |
| Analytics | Umami (self-hosted, PostgreSQL backend)   |

No build step. No transpilation. No node_modules.

---

## Project layout

```
www/            Static files served by Caddy
  index.html    Single page — full HTML structure
  style.css     All styles (CSS variables, layout, cards, animations)
  app.js        All client-side logic (prompt display, JSON parsing, profile renderer)
  analytics.js  Generated by 'make provision' — do NOT edit by hand

scripts/
  provision.sh  Idempotent — creates the Umami website and generates analytics.js

Dockerfile      FROM caddy:2-alpine; copies Caddyfile + www/
docker-compose.yml          Production stack (caddy + umami + umami-db)
docker-compose.override.yml Dev overrides — live-mounts ./www and Caddyfile
.env.example    Source of truth for all environment variables
Makefile        make up / down / logs / build / provision / open
```

---

## Environment variables (.env.example)

| Variable              | Purpose                                              |
|-----------------------|------------------------------------------------------|
| `DOMAIN`              | Public domain (nginx-proxy-manager, used by provision.sh) |
| `UMAMI_PUBLIC_URL`    | Public URL of the Umami instance (analytics script src) |
| `UMAMI_ADMIN_PASSWORD`| Umami admin password — change before first provision |
| `UMAMI_SECRET`        | Umami app secret                                     |
| `UMAMI_DB_PASSWORD`   | PostgreSQL password for the umami user               |

Keep `.env` and `.env.example` in sync.

## Dev workflow

```bash
make up        # Start caddy + umami + umami-db (docker compose up -d)
make provision # Create Umami site, generate www/analytics.js  ← run once
make open      # Open http://localhost:8200 in the browser
make logs      # Follow logs from all containers
make down      # Stop and remove containers
```

In dev, `docker-compose.override.yml` live-mounts `./www` — no rebuild needed when editing HTML/CSS/JS.

For production (Raspberry Pi): `docker compose -f docker-compose.yml up -d --build`

## UI layout

```
┌──────────────────┬──────────────────────────────────┐
│  Sidebar (1/3)   │  Profile area (2/3)               │
│                  │                                   │
│  1. Prompt to    │  Empty state until JSON is pasted │
│     copy         │  then: profile card               │
│  2. JSON paste   │                                   │
│     textarea     │                                   │
└──────────────────┴──────────────────────────────────┘
```

Profile card sections (rendered from JSON):
- Avatar (initials + deterministic colour from username hash)
- Name, tagline, model name, birth/death years
- Ton, style, persona, registre linguistique
- Forces (list), faiblesses (list)
- Contradictions (special styling)
- Speech patterns, mots interdits (chips)
- Tag scores — 20 thematic axes, animated progress bars (0–10)

All fields are required (enforced by the prompt, not by the app):

```json

  "user_name": "string",
  "model_name": "string",
  "tagline": "string (4–6 words)",
  "persona": "string (3–5 sentences)",
  "ton": "string (2–4 words)",
  "style": "string (1 sentence)",
  "forces": ["string", "string", "string"],
  "faiblesses": ["string", "string"],
  "registre_linguistique": "string",
  "contradictions": ["string", "string"],
  "speech_patterns": ["string", "string"],
  "mots_interdits": ["string", "string"],
  "tag_scores": {
    "philosophie": 0, "politique": 0, "société": 0,
    "science & tech": 0, "environnement": 0, "économie": 0,
    "histoire": 0, "art & culture": 0, "spiritualité": 0,
    "droit & justice": 0, "futur & utopie": 0,
    "psychologie & comportement": 0, "amour & relations": 0,
    "corps & santé": 0, "éducation & enfance": 0,
```

## Analytics (Umami)

`analytics.js` is generated by `make provision` and must **not** be committed with real tracking IDs.
The file is listed in `.gitignore`.
Events tracked:

| Event              | Triggered when                                  | Custom data                              |
|--------------------|-------------------------------------------------|------------------------------------------|
| `prompt_copied`    | User clicks the copy button                     | —                                        |
| `ai_opened`        | User clicks an AI shortcut button               | `{ ai: "ChatGPT" }`                      |
| `json_invalid`     | Pasted JSON fails to parse (debounced)          | —                                        |
| `profile_rendered` | A valid profile is successfully drawn           | `{ model, top_theme, is_living }`        |
| `profile_shared`   | User clicks the share (tweet) button            | `{ method: "tweet" }`                    |
| `language_changed` | User clicks a lang-bar button                   | `{ lang }` (e.g. `"fr"`, `"en"`)        |

## Key constraints

- **No build step** — keep everything in `www/` as plain files. Do not introduce bundlers, npm, or frameworks without explicit discussion.
- **analytics.js is generated** — never edit it manually; re-run `make provision` if needed.
- **provision.sh is idempotent** — safe to run multiple times. It skips creation if the Umami website already exists.
- The app renders JSON **entirely client-side** — there is no API, no server-side processing, no authentication.
- CSS animations use `anim-item` / `visible` classes with staggered `animation-delay` set in JS — do not remove these classes from HTML.
